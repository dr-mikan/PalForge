# The Nexus gallery

Four cards. Three carry the mod page's argument; the fourth answers the question every framework
page gets asked and none of them answers with a picture.

| | card | the question it answers |
| --- | --- | --- |
| 1 | `G1-new-entity.svg` | **What can I add?** A new pal, item or building — and the honest pairing that makes it possible. |
| 2 | `G2-what-you-can-add.svg` | **How many kinds of thing?** Eight, all the same shape. |
| 3 | `G3-events.svg` | **Does it react to the game?** Twenty-one channels, already wired. |
| 4 | `G4-saved-state.svg` | **Does it touch my save?** No — and the picture is two boxes that never meet, one of them the one the reader is worried about. |

⚠️ **They go IN the full description, under the heading each one explains** — not in a row at the
top as decoration. Every section still reads without its image; none of them carries information
the prose does not. `publish/nexus-full-description.bbcode` places them and
`publish/README.md` has the upload workflow, which is fiddly because Nexus only mints an image URL
after the upload.

Generated by `tools/gen-cards.py`, so the anvil, the three colours and the dashed-means-declared
rule are one definition rather than a convention. Editing an SVG here is editing build output.

## Why three, and not nine

Five comparable frameworks were read before deciding — **SMAPI**, **UE4SS**, **Fabric**,
**Harmony**, **BepInEx** — and **not one of them uses a single diagram**. Every one leads with a
logo, one sentence of the form *`<what it is>` for `<the game>`*, and a download. Harmony, which
has exactly this project's problem (a library with no visible output), is explicit about it: it
does not try to visualise itself, it explains in words and sends you to the docs.

They can afford zero because they are already known. PalForge is not, so it needs more than zero.
But nine on a mod page reads as effort spent on the page rather than on the code, which is the
opposite of what this project wants believed about it. **Three is the smallest number that answers
the three questions a stranger actually has.**

There WERE nine, one per domain, framed as *what you can extend*. They went when the page was
reframed around what a pack can **add** — and because nothing ever referenced them. Unreferenced
generated output rots. `git show 033eafc` has them.

## The design language

Every card is built from the same four things, so a reader who learns them on G1 can read G3
without being told again:

| | means |
| --- | --- |
| **the anvil**, top right | the framework itself — the chosen mark, defined once in the generator |
| **heated steel** — a solid orange-outlined box, an arrow, a spark | something that **fires**: a live channel, a real call, an event that was observed |
| **cold steel dashed** — a dashed grey box or arrow | **declared, callable, and with no native source behind it.** `skill.hit`, `building.break`, a custom sound. The one piece of vocabulary that matters most. |
| **the code panel**, left | real, callable API. Never pseudocode — if the API changes, the card is wrong and the fix belongs in the generator. |

Each card also carries one grey line along the bottom that says something true and slightly
awkward: what the measurement actually was, or what the capability does *not* promise. A gallery
that only shows the good half is the kind of page that produces the first bug report.

## ⚠️ The claim G1 exists to keep honest

**PalForge alone cannot add a row to Palworld's data tables.** Lua cannot write one. A genuinely
new item, creature or build object needs **PalSchema** for the row; PalForge's namespaced ids are
built to be exactly what PalSchema writes — `mypack:Potion` becomes the row `mypack_Potion`.

G1 draws that as two boxes and an arrow rather than putting it in a footnote, because *"add new
pals, items and buildings"* is true of the two together and false of PalForge on its own. Giving
something the game **already has** new behaviour needs PalForge and nothing else.

If this card is ever redrawn, that pairing is the part that must survive.
